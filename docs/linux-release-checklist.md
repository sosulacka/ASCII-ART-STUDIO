# Чеклист релизного теста на реальном Linux

Всё остальное (юнит-тесты, сборка, UI, захват камеры, скриптинг через
libaxium_vm.so) уже проверено в WSL — здесь ТОЛЬКО то, что WSL проверить
не может. Ожидаемое время: 15–20 минут. Подойдёт живая USB-флешка с
Ubuntu 22.04+ или виртуалка с пробросом USB-камеры.

## 1. Установка пакета (~5 мин)

- [ ] Скачать/скопировать `.deb` (или AppImage) со сборки CI
- [ ] `sudo apt install ./asciiartstudio_*.deb` — ставится без ошибок
- [ ] Приложение появляется в меню приложений (иконка, имя)
- [ ] Запускается, окно рендерится без артефактов (реальный GPU, не WSLg-RDP)
- [ ] Вкладка «Скрипты»: доступна ТОЛЬКО если рядом с бинарником лежит
      `libaxium_vm.so` — проверить оба состояния (без файла — бейдж
      «axium_vm не найдена», с файлом — редактор работает, Run печатает)

## 2. Виртуальная камера v4l2loopback (~7 мин) — ГЛАВНОЕ

WSL это не покрывает вообще (модуль ядра в WSL2 не грузится).
ВАЖНО: exclusive_caps=1 обязателен — без него Chromium-приложения
(Discord, браузеры) НЕ показывают устройство в списке камер.

```bash
sudo apt-get install v4l2loopback-dkms
sudo modprobe v4l2loopback devices=1 video_nr=10 card_label="ASCII Art Camera" exclusive_caps=1
ls /sys/devices/virtual/video4linux   # должен появиться video10
```

- [ ] БЕЗ модуля: вкладка «Камера» показывает кнопку «Установить драйвер
      камеры» → клик → polkit-диалог пароля (pkexec modprobe) → после
      успеха кнопка исчезает, устройство появляется
- [ ] В приложении: запустить камеру → «Виртуальная камера»
- [ ] Индикатор бэкенда показывает v4l2loopback (не MJPEG-фоллбек)
- [ ] В OBS: Источник → «Устройство захвата видео (V4L2)» → "ASCII Art Camera"
      — виден живой ASCII-поток
- [ ] В браузере (meet.google.com/тест getUserMedia) камера тоже видна
- [ ] Выгрузить модуль (`sudo modprobe -r v4l2loopback`), перезапустить
      приложение → включение виртуальной камеры честно сообщает про
      MJPEG-фоллбек (`http://localhost:8765/stream`), НЕ «v4l2loopback»

## 3. Камера у обычного пользователя (~3 мин)

В WSL права на /dev/video* давались руками (chmod). На реальном Linux:

- [ ] Пользователь в группе `video` (`groups` — обычно уже там)
- [ ] Захват физической камеры в приложении работает БЕЗ sudo/chmod
- [ ] getUserMedia в WebKitGTK показывает диалог разрешения и работает

## Если что-то падает

- Логи: запустить из терминала — stderr WebKitGTK/приложения виден сразу
- `WEBKIT_DISABLE_COMPOSITING_MODE=1` — если чёрное окно на NVIDIA
- `v4l2-ctl --device=/dev/video10 --info` — проверка, что loopback жив
